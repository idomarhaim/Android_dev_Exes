# Changes — 20/06/2026

> **Branch:** `Ex2`

## Round 1 — High-scores screen

Fixes reported from device testing: map markers not visible and poor contrast
on the selected row.

## 🔧 Bug Fixes

- **Selected-row contrast** (white-on-yellow → unreadable): row text colours
  are now set per state in `ScoresAdapter` — light text on the normal dark
  row, dark text on the highlighted yellow selected row — so both stay legible.
  Highlight colour tweaked to `#FFF176`.
- **Map markers / camera**: `ScoresMapFragment` now frames *all* located scores
  via `LatLngBounds` (with a single-marker zoom fallback) instead of only
  centring on the first one, so every recorded location is visible at once.
- **More reliable location capture**: on game over `GameActivity` falls back to
  `getCurrentLocation(PRIORITY_BALANCED_POWER_ACCURACY, …)` when
  `lastLocation` is null (common right after boot / on some devices), so newly
  recorded scores actually carry coordinates and show up on the map.

## ⚠️ Configuration note (root cause of the blank map)

The map renders blank/grey when the **Google Maps API key is missing**. The
build currently injects the placeholder `YOUR_API_KEY_HERE` (seen in the merged
manifest), which fails authentication, so no tiles or markers appear. Put a
real key in `local.properties`:

```
MAPS_API_KEY=AIza...your_real_key...
```

then rebuild. Existing scores saved before the location fix have no
coordinates and won't get markers; play a new game (with location permission
granted) to record located scores.

## Round 2 — Sensor-mode controls

Two tilt-control fixes for Sensor mode.

### 🔧 Bug Fixes

- **Speed direction inverted**: tilting the phone **forward** now speeds the car
  up (objects approach faster) and tilting **back** slows it down. The speed
  factor's `y` coefficient flipped from `+` to `-`
  (`1 - (y / GRAVITY) * 0.8`).
- **One lane per tilt**: steering is now edge-triggered with hysteresis instead
  of a 220 ms repeat. The car steps a single lane when the tilt crosses
  `TILT_THRESHOLD` (3.0), and won't move again until the phone returns below
  `TILT_RELEASE` (1.5). A single tilt no longer skips 2+ lanes.

### 📁 Modified Files

- `GameActivity.kt` — inverted speed sign; replaced time-cooldown steering with
  an armed/release hysteresis guard (`tiltArmed`, `TILT_THRESHOLD`,
  `TILT_RELEASE`); removed `lastTiltMoveMs` / `TILT_COOLDOWN_MS`.

### 🧪 Tests

- Tilt logic depends on live accelerometer input, so it isn't covered by the
  JVM `GameEngineTest`; verified by `get_errors` (no compile errors) and
  on-device testing. The underlying `moveCar` lane-clamping it calls *is*
  unit-tested.

## Round 3 — Tilt reaches the edge + blank-map explanation

Two more device-testing reports: the car couldn't steer all the way to the
screen edge however hard/long the phone was tilted, and the map was still
blank.

### 🔧 Bug Fixes

- **Tilt now reaches the edge lane**: steering switched from edge-triggered
  hysteresis (which only ever stepped one lane per tilt gesture) to an
  **absolute tilt-to-lane mapping**. The accelerometer `x` is mapped to a
  fraction of `MAX_TILT` (6.0) and projected onto the lanes: a gentle tilt is a
  one-lane nudge from centre, and a firm tilt drives the car straight to the
  edge lane. Added a `setCarLane()` helper that places the car on an absolute
  lane via `engine.setLane()`. Removed `tiltArmed` / `TILT_THRESHOLD` /
  `TILT_RELEASE`.
- **Blank map now explains itself**: `HighScoresActivity` reads the merged
  `com.google.android.geo.API_KEY` meta-data and, when it's empty or still the
  `YOUR_API_KEY_HERE` placeholder, shows an overlay message over the map
  instead of a mysterious blank grey area.

### ⚠️ The map is still blank because there is no API key (unchanged root cause)

`local.properties` still contains `MAPS_API_KEY=YOUR_API_KEY_HERE`. Google Maps
**cannot** render tiles or markers without a valid key — this is external
configuration, not a code bug. To fix it: create a key in Google Cloud Console
(enable *Maps SDK for Android* + billing, restrict it to package
`com.example.hw2` with the debug SHA-1), then set
`MAPS_API_KEY=AIza...` in `local.properties` and rebuild. Scores recorded
before the Round-1 location fix carry no coordinates and won't get markers.

### 📁 Modified Files

- `GameActivity.kt` — absolute tilt-to-lane steering; `setCarLane()` helper;
  `MAX_TILT` constant; removed hysteresis fields/constants; `abs` import
  replaced with `roundToInt`.
- `highscores/HighScoresActivity.kt` — detect missing/placeholder Maps key and
  toggle the overlay message.
- `res/layout/activity_high_scores.xml` — wrapped the map in a `FrameLayout`
  with a `txtMapUnavailable` overlay.
- `res/values/strings.xml` — added `map_unavailable`.

### 🧪 Tests

- **JVM unit (JUnit4)** — `GameEngineTest` unchanged; the new steering calls
  the already-unit-tested `GameEngine.setLane()` (lane clamping is covered).
  Not re-run as no engine logic changed.
- **Not run (and why)**: tilt steering needs live accelerometer input and the
  map overlay needs a device/emulator; neither is automatable here without an
  instrumented test rig. Verified by `get_errors` (no compile errors) and
