# Changes — 28/05/2026

## 🆕 New Features

- 🛑 **Game Over screen** with a **Play Again** button replaces the previous
  auto-restart behavior. Losing all 3 lives now shows a full-screen overlay
  ("Game Over" + button) instead of silently resetting.

## 🔧 Bug Fixes

- 🐛 Fixed `ConcurrentModificationException` thrown from `onTick()` when the
  third crash cleared the obstacle list while it was being iterated. The
  iteration now bails out early once Game Over has been triggered.
- 🐛 Fixed the game continuing to run silently behind the Game Over overlay,
  which caused phantom crash vibrations / toasts. A `running` flag now
  guards both entry to and re-scheduling of `tickRunnable`, and
  `stopLoop()` removes any pending callbacks.
- 🐛 Fixed crash `Toast`s stacking and lingering on screen — a single
  `crashToast` reference is kept and `cancel()`ed before each new toast,
  and again on Game Over.

## 🔧 Technical Changes

- 🔀 **Reworked movement model** per the lecturer's guidance — no
  `translationX` / `translationY` and no `Canvas`. The road is now a
  runtime-built `12 × 3` grid of `ImageView` cells plus a bottom car row.
  "Movement" is implemented by toggling each cell's `visibility` based on a
  `Boolean[rows][cols]` state array that is shifted down by one row per
  tick.
- ⏱️ Single tick driver replaces the previous separate `tick` + `spawn`
  loops. Defaults: `tickMs = 260 ms`, `spawnChance = 0.55` per tick.
- 🛠️ Pinned the Gradle JDK to **Eclipse Adoptium JDK 17** via
  `org.gradle.java.home` in [`gradle.properties`](../gradle.properties) and
  deleted the auto-generated `gradle/gradle-daemon-jvm.properties` to fix
  the `jlink.exe does not exist` build error from the Red Hat Java
  extension's bundled JRE.
